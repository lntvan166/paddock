# herdr-core Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make one paddock show and drive agents from herdr-core (the Herdr desktop app's runtime) alongside terminal herdr, in the same Agents list and Spaces screen.

**Architecture:** A second backend directory, `src/server/herdr-core/`, sits beside `src/server/herdr/`. It owns the core's socket, adapter, supervisor, actions and space tree, plus a small client for the app's own socket (renames). Agents carry an `origin`, and core ids are namespaced, so a thin composite routes each action by id. The store replaces agents per origin. The UI only ever sees `src/shared/types.ts`.

**Tech Stack:** Bun, TypeScript, Hono, React; herdr-core JSON-RPC 2.0 over a Unix socket (protocol generation 1).

**Spec:** `docs/superpowers/specs/2026-11-09-herdr-core-backend-design.md`

## Global Constraints

- **Task 1 is a gate.** If a blocked Claude Code permission prompt in the app cannot be answered through herdr-core by a supported call, STOP after Task 1. Record the findings, report, and build nothing else.
- Dependency direction: `backend/socket → backend/adapter → state/store → ws/hub → web/`. Only `src/server/herdr/` knows terminal herdr. Only `src/server/herdr-core/` knows herdr-core and the app socket.
- `src/shared/herdr-core-api.d.ts` is generated by `make types` from `hc schema` and committed. Never hand-edit it.
- Accept protocol generation 1 only. An unknown generation is refused with a message naming both numbers. Unknown fields and new enum values are tolerated, because "the API only grows".
- Never write the `herdr-app` core document (`doc.set`). Read it only.
- Write `herdr.seen` only on Dismiss or when an agent is opened (once, at the tap). Never from presence.
- No guessed keystrokes: one-tap answer buttons only where `parsePrompt` read the options and `commit` is not `"cursor"`. `status.kind` may remove buttons, never add them.
- Fixtures, demo and tests use invented names (`api-refactor`, `schema-migration`, …). No real hostnames or paths. `make check-clean` before every commit.
- No swallowed errors. A missing or unreachable core is logged once at INFO with the reason and shown in `/api/health` and Settings → Connection, and paddock keeps running.
- TUI-only behaviour and screens stay byte-for-byte the same. The full suite passes at every commit.

## Review Focus

1. **Core not installed, or stopped mid-session** (`hc server stop`, `hc update` restarts it): paddock keeps the TUI list live, drops app agents with a visible "core disconnected", and reconnects without a restart. Test: Task 7, `core supervisor drops core agents and reconnects after the socket closes`.
2. **A `missed` event or a seq gap after a laptop sleep:** the store resyncs from a fresh snapshot instead of holding stale states. Test: Task 7, `a missed event replaces core agents from its snapshot`.
3. **The same name in both backends** (an `api-refactor` in the TUI and one in the app): two rows, never merged, each opening its own terminal. Test: Task 4, `core and herdr agents with the same name keep distinct ids`.
4. **Rename while the app is closed:** a plain refusal, not a silent success. Test: Task 9, `rename refuses with OPEN_HERDR_TO_RENAME when the app socket is absent`.
5. **An app agent that finishes while the operator watches it at the desk:** no phone notification. Test: Task 11, `notifier skips a core agent whose seen is at or past its turn`.
